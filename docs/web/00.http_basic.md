## 1. History and Background of the Web
- In the past, to share papers or documents, one had to store them on disks and deliver them physically → caused distance-related problems.  
- The idea of “a dedicated protocol to share documents remotely” led to the birth of the Web.  
- (Assumption) Initially, documents were shared as `txt` files, but large amounts of text were hard to read.  
- The need arose to jump directly to specific locations in a document → not possible with plain text.  
- Therefore, a new document representation system was created → **HTML (HyperText Markup Language)**.  

---

## 2. Basic Elements that Make Up the Web

### (1) HTML
- **Definition**: Hyper Text Markup Language.  
- **Role**: Defines document structure and hyperlinks.  

### (2) HTTP
- **Definition**: HyperText Transfer Protocol.  
- **Role**: Communication protocol that transmits HTML documents between clients and servers.  

### (3) Web Browser
- **Definition**: A program that receives HTML documents and renders them visually.  
- **Role**: Acts as a **client** that sends user requests to the server.  

### (4) Web Server
- **Definition**: A program that sends the requested information as a response when a client makes a request.  
- **Features**:  
  - No request → no response.  
  - **Example**: Can be compared to a “restaurant server” → food is provided only when a customer places an order.  

---

## 3. Request & Response
- The web operates on a **1 request → 1 response** principle.  
- Multiple responses for a single request or 1 request → 2 responses should not occur.  
- Servers must always return a response corresponding to the client request → **Cookie and Session**.

### (1) Cookie
- A ticket stored on the client (browser) side (like a public note, visible and editable by anyone → low security).  
- Stored so the server can identify the user.  

### (2) Session
- A ticket stored on the server side (like a kiosk managing data internally).  
- More secure because managed by the server.  
- **Example**: When booking a movie, tickets should be issued/managed by the server for safety, not manually by the user.  

---

## 4. TCP & Handshake
### (1) TCP
- **Transmission Control Protocol**  
- Ensures data is transmitted safely and without loss.  

### (2) Handshake
- A procedure to confirm that the client and server are ready to connect.  
- Must be performed first for a stable connection.  

---

## 5. Web Server Basics
- **Root Directory**: The main folder from which the web server starts.  
- **Index (index.html)**: The default document that opens when accessed.  
- **DDoS (Distributed Denial of Service)**: A state where the server cannot respond properly due to too many simultaneous requests.
