## 1. Web의 역사와 배경
- 과거에는 논문이나 문서를 전달하려면 디스크에 담아 직접 전달해야 했음 → 거리 문제 발생.  
- “문서를 원격으로 공유할 수 있는 전용 프로토콜이 필요하다”는 아이디어에서 웹이 시작됨.  
- 초기에는 `txt` 파일로 문서를 공유했지만, 글자만 많아 가독성이 떨어짐.  
- 특정 위치로 바로 이동할 수 있는 기능이 필요 → 기존 텍스트 체계로 불가능.  
- 그래서 새로운 문서 표현 체계가 만들어짐 → **HTML (HyperText Markup Language)**.  

---

## 2. Web을 구성하는 기본 요소

### (1) HTML
- **정의**: Hyper Text Markup Language.  
- **역할**: 문서 구조와 하이퍼링크를 정의하는 언어.  

### (2) HTTP
- **정의**: HyperText Transfer Protocol.  
- **역할**: 클라이언트와 서버 간에 HTML 문서를 전송하는 통신 규약.  

### (3) 웹 브라우저
- **정의**: HTML 문서를 받아서 시각적으로 렌더링해주는 프로그램.  
- **역할**: 사용자의 요청을 서버에 전달하는 **클라이언트(Client)**.  

### (4) 웹 서버
- **정의**: 클라이언트가 요청(request)을 보냈을 때, 해당하는 정보를 응답(response)으로 전달하는 프로그램.  
- **특징**:  
  - 요청이 없으면 응답도 없음.  
  - **예시**: “식당 서버”에 비유 가능 → 손님이 주문해야 음식을 줌.  

---

## 3. Request & Response
- 웹은 **1 요청 → 1 응답**의 원칙으로 동작.  
- 한 요청에 여러 응답 또는 1 요청 → 2 응답 오면 안 됨.  
- 서버는 항상 **클라이언트 요청에 대응하는 응답**을 반환해야함 → Cookie and Session

### (1) Cookie
- 클라이언트(브라우저)가 보관하는 번호표.  
- 서버가 사용자를 구분할 수 있도록 클라이언트 측에 저장됨.  

### (2) Session
- 서버가 보관하는 번호표.  
- 서버에서 관리하기 때문에 보안성이 더 높음.  
- **예시**: 영화 예매 시, 손님이 직접 티켓을 만드는 게 아니라 서버가 발급/관리해야 안전함.  

---

### (1) TCP
- 전송 제어 프로토콜 (Transmission Control Protocol).  
- 데이터가 손실 없이 안전하게 전송되도록 보장.  

### (2) Handshake
- 클라이언트와 서버가 서로 연결할 준비가 되었는지 확인하는 절차.  
- 안정적인 연결을 위해 선행되어야 함.  

---

- **Root Directory**: 웹 서버의 시작 지점이 되는 기본 폴더.  
- **Index (index.html)**: 접속 시 기본적으로 열리는 메인 문서.    
- **DDoS (Distributed Denial of Service)**: 너무 많은 요청이 동시에 몰려 서버가 정상적으로 응답할 수 없는 상태.
