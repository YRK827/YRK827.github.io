## 2. Basic Concept of a Server

### (1) Server
- A **server** receives **requests** from clients (e.g., web browsers) and sends **responses**.

### (2) Web Server
- Sends web content (HTML, CSS, JS) in response to client requests.  
- Current focus: basic server that delivers HTML files.

### (3) Why We Create Servers
- To send responses to browser requests.  
- Without a server, the browser cannot receive responses.  
- **All technologies exist for a purpose.**

## 4. Debugging

### (1) Basic Steps
1. Click the line number → add a breakpoint (red dot).  
2. Press F5 → select Node.js debugger.  
3. Server pauses at the breakpoint when running.  
4. Use Step Over (F10) to move to the next line.  
5. Shift + F5 → stop debugging.

### (2) WATCH Panel
- Click + → type `req`  
- Inspect live request objects: `rawHeaders`, `url`, etc.  
- `req.url` example: `'/'` → root path of the domain (e.g., `https://example.com/` → `/` is the main page).

## 5. URL vs URI
- URL (Uniform Resource Locator): Specifies the location of a resource.  
- URI (Uniform Resource Identifier): Identifies a resource (URL is a subset of URI)

## 6. Request & Response Practice

### (1) Current Situation
- Requests for HTML files always return "Hello World".  
- Goal: recognize the request path and serve the corresponding HTML file.

### (2) Using Debug Console
- Type `req` or `req.url` in Debug Console to inspect requests without restarting the server.  
- No need for `console.log()` statements in the code.  
- Faster development and fewer bugs.

## 7. Server Restart Problem & Abstract Structure

### (1) Problem
- Changing code requires restarting the server.  
- In real service, downtime blocks user access → service interruption ❌

### (2) Solution: Abstract Structure
- Separate server logic by sections.  
- On each request, dynamically load the corresponding file.  
- If the requested path exists, return its content as the response.

### (4) Code Refactoring
- Move first `end()` function HTML → `index.html`  
- Move second `end()` function HTML → `section_0.html`

### (5) Shortcuts
- cmd + D → Select multiple instances of the same word  
- cmd + F2 → Select all occurrences of the same word

## 8. File Input/Output (FIO)

### (1) Why Use File I/O
- Until now, programs run only in RAM.  
- Hard disk was only for storage.  
- With FIO, we can update content without restarting the server ✅

### (2) Concepts
- File Input/Output (FIO) → Reading/writing files  
- File System (`fs`) → Node.js built-in module for file operations
