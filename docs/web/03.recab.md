# 1. 📌 Why the Web Was Created

## ■ Problems in the Past
- Each computer used different ways to exchange data → very inefficient  
- No system to “connect and view documents” in a human-friendly way  
- Sharing documents easily was difficult  

## ■ The Solution → Birth of the Web
To make document sharing easy on the internet, three core technologies were created:

1. **HTML** – document content  
2. **URL** – document address  
3. **HTTP** – the rules for exchanging documents (Protocol)  

In short:  
**The Web is a system for linking and sharing documents**,  
and **HTTP is the communication rule that enables this interaction**.

---

# 2. 📌 What Is HTTP? Why Do We Need It?

## ■ HTTP = HyperText Transfer Protocol  
A set of rules that allows web browsers and web servers to communicate.

## 🔁 How It Works
- Client (browser): “Please give me this page!” → **Request**  
- Server: “Here you go, HTML!” → **Response**

## ■ Why We Use HTTP
- All websites must follow the same rules to communicate properly  
- It acts as a shared language between browsers and servers  

📌 YouTube, Google, Naver, etc. → all operate using HTTP/HTTPS.

# 4. 📌 Route (Path) Handling
- Server checks which “path” the browser is requesting  
- If a path does not exist, the server shows `/` or an error page  

---

# 5. 📌 Hard-coded HTML vs File-based HTML Serving

## 5-1) Problems with Hard-Coded HTML
- HTML is embedded directly in server code → must restart server after editing  
- To modify HTML, you must open and edit the server file  
- Very poor maintainability  

## 5-2) Serving HTML Files (File-Based Serving)
- Separates server logic and HTML content  
- Editing only the HTML file → no server restart needed  
- Much easier to maintain  
- Represents “separation of concerns” → more abstract and flexible architecture  

---

# 6. 📌 Root Directory Concept

## ■ root directory = the top-level folder the server uses as its base  
All file requests are resolved relative to this directory.

## ■ Problems
- Root directory depends on where the server is executed  
- Folder structure becomes tied to server location → inconvenient for deployment  

## ■ Solution
- Separate the concept of the root directory  
- Allows flexible system file structure  
- Implemented in `03.http_rootdir`

# 7. 📌 Why Many Web Projects Start with an “index” File
- The Web was originally designed to distribute “documents” (like a book)  
- If there is no specific file requested, the “table of contents” (index) is shown  
- This is why the default file name is often `index.html`  
- You can change it — it’s not required to be “index”

# 8. 📌 From Static Pages to Dynamic Pages

## ■ Problems with Static Pages
Example:  
A `<nav>` header must be copy-pasted into every single HTML page  
→ Editing one menu requires modifying *all* files manually  

## ■ Solution → Dynamic Page Concept
- Let the computer generate repeated parts automatically  
- Build parts of the page programmatically  
- Template systems are introduced  

➡ This is the transition from **static pages** to **dynamic pages**.  
➡ Frameworks like React, Vue, and server template engines were born from this idea.  

---

# 9. 📌 CGI (Common Gateway Interface)

## ■ What CGI Does
- A script file that communicates with a web server  
- Extends web server functionality  
- One of the earliest ways to make web pages dynamic  

Essential idea:  
**The server runs an external program and sends its output as a webpage.**  
Languages such as PHP, Python, and Perl can be used.

---

# 10. 📌 PHP – Quick Overview
- A language that lets you embed server-side logic inside HTML  
- One of the oldest and most widely used web languages  
- WordPress and many older websites are built with PHP  
- A general-purpose programming language (like Java, C++, Python)

# 11. 📌 Cache (Caching)

## ■ Definition
A temporary storage for frequently used data  
→ HTML / CSS / JS / images / fonts, etc.

## ■ Why Caching Is Useful
1. **Faster loading**  
   - No need to download the same files again  
2. **Less data usage (reduced traffic)**  
3. **Lower server load**  
4. **Offline access**  
   - Some pages can open even when the internet briefly disconnects
