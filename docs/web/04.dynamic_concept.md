# 1. File Storage & Memory

## 1.1 Saving a File
- “Saving a file” means storing data in **secondary memory** (HDD, SSD, USB, etc.).
- When a file is saved, it is written to **disk**, not RAM.

## 1.2 Reading a File
- Reading = loading data from **secondary memory into RAM**.
- **Analogy:**  
  Requesting data is like going to a warehouse and fetching a book → energy spent traveling, searching, retrieving.

## 1.3 HDD vs SSD
- **HDD**
  - Mechanical (spinning disk)
  - Slower access speed
  - Higher energy usage
- **SSD**
  - Electronic flash storage
  - Much faster
  - Lower latency and energy usage

# 2. Cache

## 2.1 What is Cache?
- A **temporary copy** of frequently used data.
- Stored in **RAM**.
- Purpose: avoid repeatedly reading from slower secondary memory.

## 2.2 Memory Locality
- Recently or frequently used data is likely to be used again.
- Caching takes advantage of this pattern.

---

# 3. Why Servers Need Cache

## 3.1 Normal Web Request Flow
1. Browser → sends request.  
2. Server → processes and sends response.  
3. Without cache → server must re-read or re-compute the same data every time.

## 3.2 Benefits of Cache
- Reduces workload on the server.  
- Delivers faster responses to users.  
- **Example:**  
  When revisiting a website, the browser often loads cached files (not redownloading them), making the page much faster.

---

# 4. Cache Server

## 4.1 What Is a Cache Server?
- A server that stores data **entirely in RAM** (often no disk).  
- Runs alongside the main/origin server.  
- Responsibilities:
  1. Pre-store predicted request results  
  2. Serve cached content instantly when clients request it

# 5. Dynamic Pages & UX/UI

## 5.1 Dynamic Page
- A page where HTML is **automatically generated** by the server.  
- Uses templates, variables, and server logic.

## 5.2 UX vs UI
- **UI (User Interface):**  
  Visual elements — layout, colors, shapes, design.  
- **UX (User Experience):**  
  How the user interacts and feels; making behaviors intuitive and predictable.
